# web builder 设计（草案，2026-10-03）

web builder 把数据库和文档库变成用户看得懂的进度与发现页面。它通过 `tools/research_db.py` 只读数据库，通过 `tools/send_message.py` 收发消息，并遵守 `doc_library.md` 的文档和权限规则。

（原设想的 reviewer 角色已取消：实验结论由根节点实现、RLD审核后冻结的统计代码给出，worker运行统计并记录判定，数据库核对判定与比较数据一致；节点优于SOTA后由RLD亲自复核新颖性和理论正确性。）

## 1. 职责

把当前任务进度和已发现的方法以可视化方式展示给用户。展示内容全部来自数据库快照和已登记的文档；web builder不自行撰写研究结论，也不改动任何研究记录。

## 2. 分工：生成器是确定性脚本，agent负责维护它

- **生成器** `tools/build_site.py`（待实现）：读取 `export_snapshot()` 和文档库，生成静态网站。同样的输入总是生成同样的页面。
- **谁来运行：** RLD在每批工作结束或重要决定之后运行生成器（只读数据库，耗时短），不需要为每次刷新唤醒web builder agent。
- **web builder agent的任务：** 只在需要改生成器时接 `web_build` 任务，例如新视图、新图表、修复显示错误、页面变大后的性能问题。改动后用代表性测试数据生成页面并自查，再交付。
- **不能做的事：** 不写数据库；除 `task_delivery` 外不登记文档；不提交研究代码分支；不在页面里加入数据库和文档中不存在的内容。

## 3. 输入与输出

| 输入 | 用途 |
|---|---|
| `export_snapshot()` | 全部节点、实验、运行、分支、决定、任务、文档索引和关系，带 `data_version` |
| `docs/` 中已生效的文档 | 项目目标与最小实验设定、假说文档（含创建理由）、统计结果、复核、决定理由、GO/NOT GO报告、相关研究笔记 |
| 运行的过程曲线文件（`run.curve_path`） | 画loss、显存、吞吐随步数的曲线；文件缺失时标注，不报错 |
| `verify_document()` | 已生效文档的哈希是否仍然一致，不一致时在页面上标红 |

- **输出：** `research/<project-id>/site/index.html`，单文件，内联CSS/JS和数据，离线可打开，不依赖CDN或服务器。曲线按固定点数降采样后内嵌。
- **版本：** 每次生成记录 `data_version` 和生成时间，保留上一版 `site/previous.html`。
- **陈旧标记：** 数据库 `data_version` 高于页面版本时，在页面顶部标注“页面已过期”。
- **文档内容：** 先转义成纯文本再做有限的格式化（标题、列表、表格、代码块），不执行文档中的HTML，防止脚本注入。

## 4. 页面结构

```
┌────────────────────────────────────────────────────────────────────┐
│ 项目名 · 阶段1 · 状态 active · data_version 128 · 生成于 10-03 21:40 │
├─────────┬──────────┬──────────┬─────────┬─────────┬────────────────┤
│  总览   │  假说树  │ 实验结果 │ 发现    │ 时间线  │  待处理         │
└─────────┴──────────┴──────────┴─────────┴─────────┴────────────────┘
```

| 视图 | 回答的问题 | 内容 |
|---|---|---|
| 总览 | 现在进展到哪一步？ | 研究目标与最小实验设定；冻结框架版本；SOTA基线、门槛（`go_margin`）与当前筛选seed数；节点按状态与实验结论计数；GO候选数；已用资源（各运行实际节点数×时长之和，与筛选预算对照）；最近10条决定 |
| 假说树 | 探索了哪些方向，各自结果如何？ | 可折叠的树：节点颜色表示状态；徽标显示实验结论（无提升/优于父节点/优于SOTA）、最新判定、相对父节点与SOTA的主指标差、复核状态；可按状态筛选和搜索。点击节点打开详情（见下文“节点详情”）：关键时间（创建、开始验证、首次实验、首次判定、优于SOTA、完成，及距创建的时长）、创建理由与引用的相关研究、分支、各实验的seed与判定、运行、决定历史、证据链接 |
| 实验结果 | 哪些方法比父节点、比SOTA好，好多少，代价如何？ | 主指标相对SOTA的配对差点图（误差线、seed数、门槛线）；相对父节点的各指标配对差（主指标、过程loss、显存、训练时间）热力表，一眼看出“处处都差”还是有取舍；选中节点后叠加显示它与父节点、SOTA的过程曲线；可排序的表格 |
| 发现 | 找到了什么方法，哪些路走不通？ | **候选方法**：优于SOTA的节点，含方法摘要、配对差、两项复核状态，GO候选突出显示；优于父节点的节点作为可拓展方向列出。**负结果**：被消灭的节点及其理由（无提升、复核失败、用户决定放弃），避免后续重复尝试 |
| 时间线 | 研究是怎么推进的？ | 节点创建、首次实验、首次判定、优于SOTA、节点完成，实验与判定、状态决定、项目状态变化，按时间排列 |
| 待处理 | 有什么卡住了，需要谁处理？ | 尚无RLD回执的UI转交（指令、需求与问题）；判定为“差不多”待扩展seed的实验；判定为“需要RLD复核”的实验；已判定但节点结论未更新的节点；执行状态为unknown的运行；未完成和待验收的任务；等待用户决定的事项；哈希不一致或缺失的文档；页面是否过期 |

### 节点详情

| 内容 | 最低要求 |
|---|---|
| 身份 | 稳定节点ID、简明标题、所属研究或分支。 |
| 问题 | 可证伪假设或研究问题，以及什么观测能够改变判断。 |
| 关联 | 父节点、竞争解释、共享对照及相关节点；标明关系类型（探索派生、执行依赖、支持/反驳证据），能定位同一对照被哪些节点复用；不为画成树而复制独立实验，父子边不表示因果成立。 |
| 实验设计 | 主要干预、匹配对照、父产物和关键匹配条件。 |
| 证据定位 | 来源、run/attempt/job或文献标识、版本、具体产物位置；标明可用、已归档、已清理或缺失，附归档位置/清理记录及重建条件或不可恢复说明。 |
| 证据方向与质量 | 支持、反驳、无效和缺失证据分别列出；工程失败不显示为科学反驳。 |
| 结果解释 | 结果、离散度或其他不确定性、适用范围、限制与竞争解释。 |
| 阶段1评估 | 节点状态，实验结论与最新判定、seed数、相对父节点与SOTA的各指标配对差值，优于SOTA后的两项复核状态，创建时引用的相关研究，以及各项的证据引用。 |
| 决定与后续 | Leader的正式决定及理由、证据依据、下一步或停止条件、复议条件和任务owner；用户决定另列来源。 |
| 状态与时间 | 科学结论与执行状态分别列出；节点关键时间；区分证据观察时间、记录更新时间与页面生成版本/时间。 |

### 展示原则

- 不知道的显示为未知，不推断，不补全；来源或权限不足时标出，不用空白让读者以为已核验。
- 统计判定、作业执行状态和研究处置分开显示；未探索不等于失败，工程通过不等于假设成立，项目NOT GO不等于所有假设已证伪。
- 用旧框架判定的实验标注“框架已更换，结果不可比”；被清理的产物显示清理记录，不留死链；外部或离线不可访问的内容明确说明。
- 页面记录数据版本和生成时间；生成失败或未纳入最新状态时显示为过期，不沿用旧页冒充当前结果。
- 只展示有权限查看的证据。

## 5. 验收

用一组代表性测试数据验收：多层分支；一个优于SOTA并通过复核的GO候选；一个优于父节点的可拓展节点；一个“处处都差”被消灭的节点；一个判定为“差不多”待扩展的实验；一个“需要RLD复核”的实验；一个被用户放弃的节点；一个哈希被改动的文档；一个缺失的曲线文件。生成页面后检查：

1. 页面可以离线打开；
2. 六个视图都能显示，筛选、搜索和折叠可用；
3. 页面上的数字与快照一致（节点数、配对差、seed数、门槛判定、资源用量）；
4. 过期、未知、缺失、旧框架结果和哈希不一致都有明确标记；
5. 在文档中放入 `<script>`，页面不会执行它。
