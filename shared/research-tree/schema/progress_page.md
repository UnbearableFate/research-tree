# 研究进度展示与按需 UI

本规范适用于 version 3 配置、schema 23 数据库的快速筛选与增量发现工作流。`tools/build_site.py` 是确定性页面生成器；没有独立 web_builder 研究角色。复杂展示或交互分析使用临时只读 UI，普通研究不维持常驻 UI 会话。

实验结论由程序从原始 run 重算，Reviewer 经独立包装器核验关键证据，Leader 作投入与 GO/NOT GO 决定。展示不能成为实验准入门，也不能补写科学结论。

## 1. 两种读取路径

- **轻量摘要：** status/refresh 读取 DB 投影，展示当前树、结果、执行状态、资源与待处理事项。带数据版本、生成时间和 freshness；`go: null`、`eligibility_checked: false` 表示尚未做资格检查，不表示不合格。高频更新合并，不遍历全部文档、曲线或渲染页面。
- **完整页面：** 用户或 Leader 显式请求 build/pane 时才读取完整快照、适用文档和曲线；结项可生成最终快照。完整资格来自 `get_eligibility`，不是缓存标签。相同输入产生相同页面。
- **失败隔离：** 展示失败单独报告，不回滚成功的科学写入、不阻止下一实验；保留旧页面时明确其陈旧版本。
- **写保护独立：** 冻结路径与文档写保护从新鲜数据库读取授权，不依赖展示缓存；无法取得权威记录时拒绝写入，不因摘要不可用而放行。
- **版本拒绝：** 页面与摘要只接受 schema 23 的当前项目。旧格式返回迁移提示，不自动升级、补字段或输出假装有效的当前状态。

## 2. 输入与输出

| 输入 | 用途 |
|---|---|
| 轻量 DB 投影 | 当前角色、树、outcome、投入状态、执行状态与费用，不计算 GO |
| `export_snapshot()` | 节点、实验、运行、分支、决定、任务、文档索引、类型化关系及 data_version |
| 已生效文档 | 目标、问题锚点、最小设计、结果、独立评审、决定、GO/NOT GO 报告与来源 |
| `run.curve_path` | loss、显存、吞吐等过程曲线；缺失时标注，不伪造数据 |
| `verify_document()` | 生效文档哈希一致性；不一致时标红并列入待处理 |

输出为 `research/<project-id>/site/index.html`，单文件内联 CSS/JS 和数据，离线打开，不依赖 CDN 或服务器。曲线按固定点数降采样。每次生成记录 data_version 和时间，保留 `site/previous.html`。

静态页不会连接实时数据库。用 `build_site.py --check` 或宿主 check 对比版本，陈旧时显式重建；生成版本与证据观察时间分别显示。文档先转义再作有限格式化，不执行其中的 HTML、脚本或外部指令。

## 3. 六个视图

| 视图 | 内容 |
|---|---|
| 总览 | 目标与最小设定、冻结框架、baseline 与有效配对进度、门槛、当前状态计数、已用/已承诺资源、最近决定。只有完整资格检查后才显示 GO 候选数 |
| 假说树 | 可折叠的思想 ancestry；代码起点、比较参照和投入处置另列。稳定节点 ID、执行状态、positive_signal/negative_signal/inconclusive、active/paused/retired、candidate_ready/confirmed 彼此分开 |
| 实验结果 | 相对显式参照和 SOTA 的配对效应、离散度、seed/独立单元数、门槛和保护指标；列清 method/claim/evaluation 身份、代码与科学配置、原始运行和曲线 |
| 发现 | 现行证据支持的候选、研究发现与负向/不确定发现；注明范围、评测类型、原始来源、独立确认及五维复核状态。工程失败不是科学反证，未探索不是已否定 |
| 时间线 | 候选 revision、节点创建、运行/attempt、evaluation、投入决定、冻结/确认材料使用、独立评审及项目决定，按真实记录时间排列 |
| 待处理 | 未接收或未落实的用户指令、待验收任务、unknown 作业、预算/权限决定、缺失或变更证据、OPEN obligation、待收集 review ticket、页面陈旧及清理未完成项 |

## 4. 节点详情

| 内容 | 最低要求 |
|---|---|
| 身份与范围 | 节点 ID、问题锚点、候选 ID/revision、固定的执行 actor；根节点只显示 architect/root，假说只显示对应 Worker |
| 可证伪设计 | prediction、intervention、comparator、resource_ceiling、stop_conditions，及实际配对与资源申请 |
| 四种关系 | 思想来源 parent_id/typed relations；代码起点 code_parent_id/base_commit；comparator_experiment_id；投入 disposition。思想父节点不表示获胜或因果成立 |
| 证据 | evaluation、run/attempt/job、manifest/原始指标/文献 ID 与版本、来源路径；可用/归档/已清理/缺失分别显示，附清理账本或归档位置 |
| 解释与限制 | 实测结果、离散度、比较单位、适用场景、竞争解释和评测类型所限制的措辞；不把代理或模拟结果写成真实任务 SOTA |
| 独立确认 | 冻结方法/主张/参照、batch、声明材料、使用状态与当前确认结果；部分 baseline 或搜索正向信号不能显示为已确认 |
| 最终资格 | 当前独立五维复核、未决问题、get_eligibility 结果及原因，明确检查时间；未经检查显示未知 |
| 决定与后续 | Leader 的正式决定、证据与理由、下一步、停止与复议条件；用户决定另列来源，任务完成与科学成立分开 |

不复制独立实验来画树；同一对照被多节点复用时可定位到同一来源，不重复累计样本或费用。统计上的正向信号、节点可继续投入、候选资格和项目 GO 是不同事实。

## 5. 验收

用明确标注的夹具覆盖：多层思想关系与不同代码起点、未获胜父节点的变体、部分 baseline、正向/负向/不确定结果、不同投入处置、已确认且复核合格的候选、工程失败、unknown 作业、OPEN 问题、过期 evaluation、缺失曲线和哈希不一致文档。另验证旧 schema 被拒绝且不修改文件。

1. 六个视图能离线显示，搜索、筛选和折叠可用
2. 数字与快照一致，原始证据、独立单元和资源不重复计数
3. 轻量 GO 为 null 且 eligibility_checked 为 false；完整检查有当前依据
4. 未知、过期、缺失、已清理和哈希异常都有明确标记
5. 文档中的 `<script>` 不执行，页面不注入来源中没有的结论
6. 显示失败不影响已经提交的科学记录；写保护不依赖展示缓存

页面代码维护属于插件工程工作，不新增科研角色或开放科学写权限。源码、两端适配器和测试应共同遵守本规范。
