# 11 横切：测试、验收与整体工作流对照实验

## 1. 测试与验收设计

### 1.1 测试层次

既有数据库、页面、消息、准备流程和适配层测试应保留。[S06]、[S07]、[S09]

新增测试分为：纯函数计算测试、真实数据库事务集成测试、平台适配器故障注入测试、真实宿主小型流程测试和整体研究对照实验。前几层不需要大规模 GPU 预算。

### 1.2 数字与协议测试

| 编号 | 场景 | 预期结果 |
|---|---|---|
| M01 | 所有 run 均为 70.0，却传入均值 70.3 | 拒绝；不产生错误 Evaluation |
| M02 | 方法与 baseline 原始值相同，却传入正差值 | 拒绝；权威差值为 0 |
| M03 | lower-is-better 指标按相反方向计算 | 使用 MetricSpec 得到正确方向，拒绝旧错误声明 |
| M04 | 0.701 与 0.699 的准确率输入 | 输出 0.2 个百分点的差值 |
| M05 | 输入混合 fraction 与 percentage 数字 | 明确转换或拒绝，不静默比较 |
| M06 | n=1 | SD/区间缺失并说明，不填 0 |
| M07 | NaN、Inf、非法范围或计数 | 无效输入，不能 GO |
| M08 | seed 相同但数据切分/协议不匹配 | 配对失败 |
| M09 | baseline 平均值接近零，采用相对比较 | 返回未定义，不丢弃不利结果 |
| M10 | 同一个 attempt 重复导入 | 幂等，无重复独立样本 |
| M11 | 相同输入重复计算 | 科学输出一致；不因时间戳产生新独立证据 |
| M12 | 实验参数与已登记协议不一致 | 拒绝进入同一比较组 |

状态机测试夹具应提供自洽数字，或明确只测试状态而不绕过生产入口。不得通过放松生产校验来维持旧夹具通过。

### 1.3 资格失效测试

| 编号 | 场景 | 预期结果 |
|---|---|---|
| E01 | 旧候选通过后更换 harness | 当前 eligibility 失效；历史 GO 保留 |
| E02 | 更换 baseline | 必须重新比较，不沿用旧领先 |
| E03 | 候选代码变化 | 方法相关复核失效 |
| E04 | 某 run 之后被证明无效 | 依赖 Evaluation 失效 |
| E05 | 只修改页面样式 | 科学资格不变 |
| E06 | 父节点追加实验 | 已创建子实验的比较参照不漂移 |
| E07 | 锁外计算期间协议改变 | 写入时发现变化并拒绝 |
| E08 | 锁外计算期间无关节点更新 | 不造成无意义重算 |
| E09 | 篡改缓存 beats_sota/pass 字段 | 不能绕过 eligibility |
| E10 | 已关闭项目出现新失效记录 | 更新有效性提示，不自动开启研究 |

### 1.4 不确定性与搜索测试

| 编号 | 场景 | 预期结果 |
|---|---|---|
| U01 | 一个 seed 轻微负向 | 可保持 inconclusive，不强制科学剪枝 |
| U02 | 达到 seed 上限仍接近门槛 | 允许 inconclusive |
| U03 | 一次工程失败 | 不产生科学负向证据 |
| U04 | 搜索最佳候选未独立确认 | candidate_ready，而非确认完成 |
| U05 | 确认反馈被用于修改代码 | 新候选不能继续宣称同一次确认是未见检验 |
| U06 | A 和 B 单独无收益，组合有明确依据 | 允许预算内组合实验，不要求先伪造父节点正向 |
| U07 | 反复更名提出等价已排除方案 | 提示重复证据并阻止无限修复循环 |
| U08 | 无值得探索的新机制 | 不为用完探索份额制造任务 |
| U09 | 保护指标超出预设退化限度 | 不自动 GO，保留真实主指标收益 |
| U10 | 新增 seed 与旧数据重复 | 不增加独立重复计数 |

### 1.5 预算与恢复测试

| 编号 | 场景 | 预期结果 |
|---|---|---|
| B01 | 两个进程同时争用最后一份额度 | 只能准入预算允许的提交 |
| B02 | 同一 submission_key 两次请求 | 返回同一预留/提交身份 |
| B03 | 调度器收到请求但返回超时 | held_unknown；不自动再提交 |
| B04 | 预留后、提交前执行器崩溃 | 安全接续同一意图，不重复占额 |
| B05 | job_id 写回前崩溃 | 通过提交身份找到原 job |
| B06 | 重复终态/结算通知 | 只结算一次 |
| B07 | 取消请求超时 | 保留预占直到状态明确 |
| B08 | 实际用量超额 | 保存真实支出，暂停准入并报告 |
| B09 | 所有训练失败 | 已花费用仍计入总量 |
| B10 | 单一 job 运行多个 seed | 计算分配不重复计费 |
| B11 | worker 会话重启、训练还在运行 | 不增加科研 attempt，不重跑 |
| B12 | 查询短暂不可用、job 已完成 | 待查询恢复后结算，不把缺失当零用量 |
| B13 | 迁移后旧进程迟到写入 | 拒绝不兼容写入，保留原作业身份 |
| B14 | 搜索额度耗尽但保留确认额度 | 搜索停止，批准范围内确认仍可执行 |

### 1.8 发布前的硬验收

全部 P0/P1 对应的确定性与集成测试通过；两端适配器均完成一次小型端到端流程：建项目、确认、基线、一个方法、结果导入、追加重复、候选复核、结项。

至少验证一次会话中断后的接续，以及一次提交结果未知后的对账。可先用模拟调度器检验，再用用户批准的低成本真实作业确认平台路径。

发布说明必须区分模拟测试、真实宿主测试和真实 GPU 训练。测试数量本身不是科学可靠性证明。

## 2. 整体工作流对照实验

### 2.1 为什么需要整个流程的实验

单元测试证明约束被执行；不能证明编排后的研究更有效。需要回答：同样模型与预算，额外管理是否减少了错误决策并提升有效探索。

autoresearch 适合作为低开销参考；DeepScientist 和 AI Scientist-v2 提供更复杂的探索参考，但初期无需先把所有系统适配到同一环境。[R06]、[R05]、[R07]

### 2.2 三个主要对照

| 系统 | 定义 |
|---|---|
| A：单 agent 简洁循环 | 相同工具与实验任务，使用最小修改—运行—评估流程 |
| B：当前 research-tree | 固定基准版本或实施前冻结版本 |
| C：改进版 research-tree | 在 B 基础上增加本设计选定机制 |

控制模型版本、可用工具、初始材料、计算预算、并行资源、任务起点和用户介入条件。对 A 不能故意剥夺 B/C 自带的关键任务说明或可用 baseline。

### 2.3 任务组合

先使用可控的测试问题，再进入少量真实研究题目：

| 类型 | 目的 |
|---|---|
| 已知零效应或只有噪声 | 测量错误 GO 与挑噪声倾向 |
| 已知有可恢复收益 | 测量能否找到并确认改进 |
| 小样本方差较大 | 测量追加重复与不确定性处理 |
| 两个机制组合才有效 | 测量非贪心探索与关系表示 |
| 易混淆的竞争解释 | 测量是否发现更便宜的替代解释 |
| 注入环境或提交故障 | 测量恢复、重复提交和经验复用 |
| 真实短程 ML 方法探索 | 检查上述机制是否迁移到真实工作 |

可控任务的真相与随机生成规则由评测环境掌握，不写进 agent 提示词或可读目录。真实研究任务通常没有穷尽的真值，因此不能把未找到改进都算作错误 NOT GO。

### 2.4 核心指标

| 指标 | 定义与注意事项 |
|---|---|
| 独立确认收益 | 候选冻结后在未用于选择的评测中测量；不是探索最大值 |
| 错误 GO | 在已知无实际收益的可控任务中输出 GO 的研究运行比例 |
| 过早淘汰 | 已知存在可发现收益的方向在足够机会前被错误排除；只对可控任务定义 |
| 有效实验效率 | 验收通过的独立实验 / 实际计算支出，失败成本也计入 |
| 重复故障率 | 已有适用 verified lesson 后仍重复同类根因的次数 |
| 重复作业率 | 非计划的重复外部提交比例 |
| 用户负担 | 人工介入次数和耗时，区分科研决策与环境救援 |
| 编排成本 | 所有 agent 的 token、费用和管理等待时间 |
| 恢复时间 | 故障发生到正确接续的时间，不以“重开了一个会话”代替恢复 |
| 探索覆盖 | 已验证机制类别、重复候选比例及组合路径；不单看节点数量 |

不同任务的收益尺度不直接平均。可以报告按预定义实际收益阈值归一化的效应，但也应保留每项任务结果，避免聚合隐藏失败。

### 2.5 重复单位

需要重复整个研究过程：改变 agent 运行随机性、任务实例或起始条件，再统计每次研究的输出。仅给最后一个候选多跑几个训练 seed，不能测量研究工作流本身的稳定性。

初期每个系统、每类任务 5 次完整研究可作为工程性 pilot，不作为统计功效充分的保证。正式比较根据 pilot 的波动与预定效应确定样本量。

同一组任务实例可在 A/B/C 之间匹配；每个系统的历史记忆与工作目录相互隔离。比较“有记忆”时，预先定义训练经验集和未见测试任务，禁止把测试题答案预先写入记忆。

### 2.6 成本口径

计算预算包括基线、失败训练、调试、确认、重试以及非计划重复的实际成本。一次性环境准备成本与重复研究成本分别报告。

复用同一基线时，各系统采用一致口径：共同预先提供，或都计入获取成本。不能让改进系统免费获得历史结果，却要求基线系统每次重新训练。

固定硬件并发额度，并同时报告 wall-clock 与资源时长，避免把更多并行资源造成的加速误认为研究策略更优。

### 2.7 消融顺序

先比较 B 与只加 D1/D2 的版本，验证完整性修复不引起流程阻塞；再增加 D3/D4，观察误判与确认成本；随后单独加入预算恢复、经验检索、非贪心探索和候选定向复核。

不要一次加入所有机制后只报告一个最终数字，否则无法识别收益来自哪项改动，也无法发现某个机制只是增加开销。

### 2.8 决策标准

确定性错误与重复提交类问题使用零容忍验收。研究收益采用预先声明的比较标准：至少不能靠提高错误 GO 获得更多“发现”；新增开销应换来独立确认收益、稳定性或人工负担的改善。

若某项 memory 或复杂搜索在对照中没有收益，保持可关闭或后置，而不是为维护设计叙事而强制保留。
