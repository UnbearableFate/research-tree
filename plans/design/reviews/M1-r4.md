**Verdict:** no CRITICAL, one MAJOR, ten MINOR, so M1 does not yet meet the "no CRITICAL/MAJOR" bar of 14 §1 step 5. I could only read files, so I have not confirmed that any test passes.

**What holds up** (read in full: `metrics.py`, `evidence.py`, `research_db.py`, the schema, `create_db.py`, the M1 test classes, both adapters' prompts and allowlists, rules, `doc_library.md`):
- **Numbers:** every statistic is recomputed from registered runs. `record_verdict` only cross-checks caller numbers, and the write transaction re-compares the input signature (`EVIDENCE_CHANGED`).
- **GO:** `go_candidates` and the GO decision both go through `_eligibility`, which reads evaluations, not cached labels. The staleness cases of 05 §3.4 are covered except the frozen file set (the MAJOR).
- **r3 fixes:** the gate-stated-once check, `preview_evaluation`, `STATISTICS_CHANGED`, full manifest retention and the baseline-retraction links are all in the code with tests.
- **Test ids:** M01–M12, E01–E10, K08 and F01/F02 exist and go through production entry points. Raw property writes only simulate tampering and old records.
- **Hosts:** both read-only allowlists equal `READ_METHODS`, pinned by `tests/test_packaging.py`. Worker and planning prompts describe the same manifest, import, evaluate and evidence-block flow.
- **Migration:** a v6 database is refused for writing until `--upgrade`; migrated evaluations never support GO.

**The MAJOR:** an evaluation is bound to `harness_ref` only, not to `harness_paths`.
- `update_project(harness_paths=[...])` with the same `harness_ref` keeps the SOTA baseline and leaves every evaluation current.
- `_check_harness` then compares only the remaining paths, so a later node experiment may change evaluation or statistics code and still be compared with the baseline.
- That experiment can become GO-eligible. Unlike a protocol change, this needs no user instruction once experiments exist.
- It needs an RLD action, which is why I rate it MAJOR and not CRITICAL.
