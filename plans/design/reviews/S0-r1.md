## 评审原文

Review complete. Here is the assessment of stage S0.

**Scope of this review.** No scenario records exist under `plans/design/test-logs/scenarios/`, and the status file marks both hosts' real scenarios NOT_STARTED, so this is a pre-scenario code review. Nothing below treats the scenarios as run.

**What holds up.** The ToyOpt Lab base is genuinely real-compute. Training reads fixed JSONL splits whose identity is a content hash, counts accuracy from predictions, derives loss from model outputs, and writes model, predictions, curve, log and manifest. The scorer reloads the model and the split independently and is shown to ignore a doctored metrics file. The adapter really starts a supervised subprocess per submission key, records PID plus process start ticks, measures CPU and wall time with wait4, refuses a second process for the same key, and supports the declared fault windows. The record validator rejects PASS without host, observed model, commands, existing raw evidence, observer output or resume evidence, and sends any substitute to reg or simulation. All five REG ids exist and exercise the behaviour through the generator and adapter entry points. The §4.4 bug fixes are implemented in shared code with tests: project lookup from subdirectories, uniform input resolution, shared literature throttle honouring Retry-After, pypdf fallback inside the injection filter, help listing optional parameters, skills check with close names, discovery artifact requirement, metric-spec takeover or refusal with an explicit replace flag, background review tickets, and the receipt check before redelivering a UI message. Both adapters expose the same research_review schema including the ticket field, and both planning prompts carry the skills check.

**Gaps.** Three items I rate MAJOR. The §3.4 S0 deliverable of measured per-run cost and a frozen budget table is absent from the status file and the scenarios README, which only asserts that the reference configuration was calibrated. The adapter's extra-launch fault runs the duplicate with the identical command, so the orphan process overwrites the primary run's manifest, metrics and model in the same output directory, which undermines the S6 attribution it exists to test. The harness-freeze fix only exempts sanity, while the rules and the Claude planning prompt still tell the RLD to freeze after reviewing baseline results, which the database refuses to create before the freeze. The remaining findings are minor: the Codex tool description promises a ticket its synchronous path never issues, the observer does not check curve length or artifact presence, the record validator does not compare reviewer observed models with the matrix, the rename clause of REG-S0-05 reduces to a hash comparison, the generator has no private-material mode, a pending ticket can be lost if the host kills the process early, and the model precheck lacks a raw evidence path.
