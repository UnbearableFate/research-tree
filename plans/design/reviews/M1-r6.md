The P0 number loop is implemented as 04/05/10 describe it, and I found no CRITICAL. There are two MAJOR findings, so by 14 §1 step 5 the batch is not complete yet. I could only read files, so nothing here is a statement that the tests pass.

- **Docs**: rules, `doc_library.md`, README (upgrade path), config template comment and the demo follow the new contracts, with the small gaps listed below.

The two MAJOR findings:

1. **`config apply` / confirm can leave a half-applied configuration.** `update_project` now refuses a `go_margin` that differs from the metric specification's `minimum_practical_gain`. `apply_config` was not adapted: it registers the new config version, supersedes the old one and rewrites the marker before that refusal. The displayed gate then differs from the enforced one, which breaks the "a refused change registers nothing" behaviour pinned in `test_research_tree.py`.
2. **M05 is only partly implemented.** The unit-mix check compares the means of the two sides. One fraction among percentages inside one experiment passes a `[0, 100]` range and is compared silently. With a baseline of 69.9, 69.9, 0.699 the method "beats SOTA" by about 23 points.
