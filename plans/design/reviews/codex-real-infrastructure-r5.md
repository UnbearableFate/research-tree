**Review of the Codex real-host infrastructure batch (M0, M6)**

I read the design files 01, 02, 09, 10, 11, 12 and 14, all eighteen changed files, the Codex adapter tests, the shared review-wrapper and discovery tests, the packaging tests, the Claude adapter's lens and spawn code for parity, and the batch's own test logs and the fourth review record.

**What holds up.** The Codex adapter now has a formal `research_control lens` entry gated on planning phase, `discovery.mode: full`, a configured lens and `models.lens_assistant`, with a fixed `assistant/lens_*` identity, read-only sandbox, read-only database access, no messaging and no review; two adapter tests drive that through the production `Runtime` and a real supervisor subprocess. The hook records an observed model per actor and session on SessionStart and PostToolUse without duplicates, and `review_call.leader_model` reads exactly those records, so a project initialised inside a live Codex session satisfies 09 §2.1 step 3. The three timeouts are correctly ordered and pinned by a test. The six-tool set in the install check equals `codex_mcp.TOOLS`. The `research_message` runtime now gives an actionable error for missing fields and for the `notice`/`blocker` types. The Claude-CLI schema transport strips only the dialect annotation and a test checks every kind's schema still validates and rejects invalid output. R01–R08, R14, R18–R22 exist in `test_review_call.py` and R09–R13, R15–R17 in `test_discovery.py`, and they exercise the behaviour through the production entry points. The previous round's documentation items (skill, root README, plan template, rules line 19) are fixed as described.

**Gaps.** The batch is still not complete under 14 §6: the records themselves say the M0 root flow on Codex stopped at M0r4 and M6's user-seed scenario has not run, and no same-family R04 counterexample is logged for this batch. The lens assistant still drifts between hosts: Codex gates and read-only-sandboxes it, Claude registers it with `Write` and does not gate its spawn at all; the rules describe the write difference but not the gating difference. The init-time reviewer-backend check that 01 §3 requires when discovery is on is not implemented on either host, which is exactly why M6r2 only discovered the Claude CLI problem at D4. Two smaller points: the lens identity is derived from the lens name alone, so seed lenses for different user hypotheses serialise under one identity, and the Claude `--max-budget-usd` floor lets a single call overshoot the alert by up to one cent.
