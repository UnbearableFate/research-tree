## 评审原文

**Review of M7 (findings, lessons, context pack, capture filter, threat scan)**

The core of 08 §1, §3 and §4 is in `shared/` and is wired through the production entry points: `set_document_current` validates finding and lesson front matter via `memory.check`, screens the fix with `capture_filter`, blocks strict-scope threats including the new authority class, checks that evidence ids and evidence runs exist, and `context_pack` builds a deterministic, size-capped pack that `resume_package` attaches. Both adapters carry `context_pack` in the read-only allowlist, a packaging test pins the three lists together, and the worker prompts on both hosts carry the same memory instructions. Tests K01 to K05 exist in `test_memory.py` and go through `register_document` and `set_document_current` rather than bypassing them. Rules, README, doc_library §4, SQL and the config template and schema were updated.

Two design items are only partly done. First, 08 §2 requires literature abstracts and fetched full text to pass `threat_scan` before they are fed back to the Leader. The only scan is at registration of the literature document, which happens after the Leader has already read the `search` output and the cached PDF. Second, K02 and 08 §1.5 say a lesson must be flagged for recheck when dependency versions, hardware, data protocol or model change. `memory.applicability` compares only `harness_ref` and `config_doc_id`. Protocol and metric-spec document changes are tracked on the project record but not compared, and the `applicability` keys the doc_library tells authors to fill (platform, dependency versions) have no effect.

The rest is naming and dead configuration: the doc type is `lesson` where 10 §1.3 says `execution_lesson`; `context_pack`'s argument order differs from the design and `role` changes nothing; `memory.enabled` and `memory.cross_project` are required by the schema but never read, so K05 holds only because no cross-project path exists; the pack size cap is fixed rather than configurable; and doc_library's directory tree and write-permission table do not list the new directories.
