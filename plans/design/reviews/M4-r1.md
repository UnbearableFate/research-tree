## 评审原文

**Review of batch M4 (reviewer backend and candidate recheck)**

The core of the batch is in place and matches 09 closely: `review_call.py` routes by provider prefix with no fallback, prechecks each backend, enforces `require_cross_family` from the observed Leader model, runs one follow-up in the same session, validates per-kind JSON Schema plus the conditional checks, refuses an observed model that differs from the requested one, writes the review document with the required front matter and raw output, and registers it through a reviewer-only `register_review`. The seven schema and prompt files exist, the novelty VERDICT LIMITS block is in the prompt, `DOC_AUTHORS["review"]` is reviewer-only, `supersede_document` refuses reviews from other roles, both hosts expose `research_review`, both Bash guards reject `pi` and `claude -p/--print` and the `reviewer/` actor, `reviews` is in both read-only allowlists, and the SQL spec, doc_library, rules, README, SKILL, Claude workflow prompt, config template/schema and demo were all updated. Test ids R01–R08, R14 and R18–R22 exist in `test_review_call.py` and go through `review_call.main` with fake `pi`/`claude` binaries; `CandidateRecheckTest` covers the eligibility binding. Schema version 10 with an additive upgrade and the v6 upgrade test are present.

What I found wrong or missing:

- **Confirmation evaluation is never rechecked.** Under the default `stage1_confirmed` profile GO rests on the confirmation evaluation, but numbers/protocol rechecks are bound to the latest search-stage evaluation only; a recheck registered against the confirmation EV is reported as stale. This contradicts 07 §3/§6.
- **K06 is not enforced or tested.** `evidence_paths` may be empty and nothing checks that a `method_code` pass cites code; `review.require_method_code_alignment` is accepted by the schema but used nowhere.
- **Concurrent reviews corrupt documents.** RV numbering and the document file are allocated without a lock; two parallel `research_review` calls (which the Claude host allows) take the same RV, the second overwrites the first's registered file and then fails registration.
- **Host timeouts drift and are shorter than the wrapper's own budget.** Claude kills at 1200 s, Codex at 1800 s, while the wrapper may legitimately run two rounds of `timeout_s` (900 s default) plus prechecks; a kill skips `log_call`, so the cost is not counted toward `review_usd_alert` and no attention item appears.

Minor items: pi continuation omits `-c`, `--no-session-persistence` is never used, Codex tool schema lacks the enums the Claude schema has, the rules §1 role table has no reviewer row, the site shows stale rechecks only as "未完成" without the old basis, the project's `review_cost_usd` excludes failed calls while the alert includes them, `init` does not probe the reviewer backend (01 §3), `REVIEW_BUDGET` is not in 10 §1.6, and neither host's `research_review` handler is exercised by a test.
