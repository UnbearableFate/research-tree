I could only read files, so nothing here was executed, including the test suites.

**What holds.** The core of M1 is implemented as designed:
- Statistics are recomputed from runs (`_compute`), and `record_verdict` only cross-checks the caller's numbers.
- Evaluations are append-only and bound to runs, code, harness, protocol, metric spec and references.
- References are fixed when the experiment is created.
- GO is re-checked inside the write transaction through the same `_eligibility` that `go_candidates` uses.
- The write-time signature check compares the entities involved, not the global `data_version`.
- Every test id M01–M12, E01–E10 and K08 exists and goes through production entry points; `raw()` is used only to simulate tampering and old records.
- The read-only allowlists are identical in `research_db.py`, `register.tsx` and `codex_hook.py`, and the worker and planning prompts say the same thing on both hosts.
- The demo is generated through `import_run_result` and `evaluate_experiment`.

**What does not hold.**
- **Protocol change (CRITICAL).** A protocol or metric-spec change does not actually retire old evidence. The SOTA baseline is kept, `match` and `required_counts` are checked only at import time, and a plain re-evaluation produces a "current" evaluation from runs made under the old protocol.
- **Document number check.** A result document can cite itself as the source, reports without a block are not checked, and numbers outside the block are never looked at.
- **Evaluation type label.** The protocol is optional, so evaluations and GO can carry no `eval_type`.
- **Migration.** The schema went from 6 to 7 with no upgrade path or version gate, and `migrate_evaluations` gives order-dependent eligibility.
- **Gate display.** The page and the Claude planning prompt show `go_margin` as the gate while the code applies `minimum_practical_gain`.
